# Raspberry Pi 400

A Pi 4 built into a keyboard. Same chip as the Pi 4 Model B and the CM4
(BCM2711). This page covers what we know from Raspberry Pi's documents,
the devicetree and our own runs on the lab's Pi 400 (pi-tests rows 295,
325, 351–377, 410, 411). Overview of all models:
[models.md](../models.md).

## Board

| | |
|---|---|
| SoC | BCM2711C0 |
| ARM | 4 × Cortex-A72 (ARMv8-A, AArch64), 1.8 GHz, 1 MB shared L2 |
| VPU / GPU | VideoCore VI: VPU as on the VideoCore IV, V3D 4.2, HVS, five pixel valves |
| RAM | 4 GB LPDDR4-3200 |
| Crystal | 54 MHz |
| USB | VIA VL805 USB 3 controller on PCIe Gen 2 x1: 2 × USB 3, 1 × USB 2, and the keyboard |
| Ethernet | gigabit: GENET v5 MAC in the SoC, Broadcom BCM54213PE PHY |
| Wi-Fi / Bluetooth | Cypress CYW43455, 2.4 and 5 GHz, Bluetooth 5.0 |
| Display | 2 × micro-HDMI, up to 4Kp60 on one |
| SD card | microSD on EMMC2 |
| GPIO | 40-pin header at the back (Pi 4 layout, seen from behind, so photos of a Pi 4 show it mirrored) |
| Revision code | ours: `c03131` (Pi 400 rev 1.1, 4 GB, Sony UK); U-Boot prints `RPI 400 (0xc03131)` |
| MAC prefix | ours: `d8:3a:dd` (newer Raspberry Pi range; older boards use `b8:27:eb`, `dc:a6:32`, `e4:5f:01`) |
| Supply | 5 V, 3 A over USB-C |
| Not on the board | camera and display connectors, audio jack, PoE |

## Address maps

| Range (ARM physical) | What |
|---|---|
| `0x0_00000000`–`0x0_3FFFFFFF` | the first 1 GB of SDRAM (the VPU's part at its top) |
| up to `0x0_FBFFFFFF`, then `0x1_00000000`… | the rest of the 4 GB |
| `0x0_FE000000` | peripherals in "low peripheral" mode (default); bus address still `0x7E000000` |
| `0x0_FF800000` | ARM local block (as on the 3B+, now mostly unused with the GIC) |
| `0x0_FF840000` | GIC-400 distributor and CPU interface |
| `0x0_FD500000` | PCIe host bridge registers |
| `0x0_FD580000` | GENET |
| `0x6_00000000` | PCIe outbound window: CPU `0x6_00000000` = PCI `0xC0000000`, 1 GB |

Devicetree buses nest: `/soc`, `/scb` (GENET, PCIe), `/emmc2bus`, each
with its own `ranges`. Drivers must translate through all levels.

## Boot

1. **Boot ROM**, then the **bootloader in the SPI EEPROM** on the board (not
   a file on the card). It reads its own settings (`BOOT_ORDER`,
   `TFTP_PREFIX`, `BOOT_UART`, …, edited with `rpi-eeprom-config`).
2. It loads `start4.elf` and `fixup4.dat` from the SD card, USB or the
   network. Network boot needs no card at all.
3. `start4.elf` reads `config.txt` (sections `[pi4]`/`[pi400]` apply),
   loads `bcm2711-rpi-400.dtb`, and starts the ARM with the built-in
   `armstub8-gic`, which also sets up the GIC-400.
4. Cores 1–3 wait on a spin table (`0xD8`…`0xF0`), as on the 3B+.

What we saw:

- If the EEPROM is set to `BOOT_ORDER=0xf21` but a card in the slot
  doesn't boot, the Pi 400 stayed silent instead of falling through to
  network boot (row 325).
- Without `BOOT_UART=1` the serial console stays empty until U-Boot.
- No card: U-Boot reports `Card did not respond to voltage select`.

## ARM

- **Interrupts:** GIC-400 (GICv2), 256 interrupts; IPIs are GIC SGIs. The
  kernel log: `gic: Distributor supports 4 CPUs and 256 IRQs`.
- **Timer:** the generic timer at 54 MHz, not 19.2 MHz.
- **Starting cores:** spin table from the firmware's stub. PSCI only with
  TF-A (Raspberry Pi's
  [arm-trusted-firmware](https://github.com/raspberrypi/arm-trusted-firmware))
  loaded as `armstub`.
- **DMA limits:** the legacy DMA engines reach only the first 1 GB; PCIe
  inbound DMA reaches the first 3 GB. With `total_mem=1024` U-Boot sees
  947 MiB.

## Peripherals

Same blocks as the BCM2837 at the same bus offsets where they exist
(GPIO, PL011, SPI, I2C, PWM, mailbox, watchdog, clock manager), plus:

| Block | Notes |
|---|---|
| more UARTs | 4 more PL011s (UART2–5), alternative pins on the header |
| more SPI, I2C | SPI3–6, I2C3–6 |
| EMMC2 (`mmc@7e340000`) | SDHCI 3.0, the SD card |
| GENET v5 (`0xFD580000`) | gigabit MAC with DMA rings; revision `0x06000000` on ours |
| PCIe (`0xFD500000`) | Broadcom's own host bridge: no ECAM, config access through an index/data register pair, own MSI controller; bridge ID `14E4:2711`, revision `0x304` |
| RNG200 | a newer random number generator |
| thermal | sensor in the SoC |

The SDHOST and Arasan controllers of the 3B+ are still in the chip but
not wired to the card. There is no DWC2 USB port in use on the Pi 400.

## USB and the keyboard

```
PCIe bridge 00:00.0 (14E4:2711)
└─ 01:00.0 VL805 xHCI (1106:3483), BAR0 at PCI 0xC0000000, 4 KB
   ├─ USB 3 ports ×2
   ├─ USB 2 port
   └─ the built-in keyboard (USB HID)
```

- The VL805 has no flash of its own on the Pi 400: the VideoCore loads its
  firmware. The ARM must ask for it through the mailbox
  (`NOTIFY_XHCI_RESET`) after every PCIe reset; Redox's `rpi-firmwared`
  logs `VL805 at PCI 0x00100000 reset, firmware loaded`.
- U-Boot reports `PCIe BRCM: link up, 5.0 Gbps x1 (SSC)`, `USB XHCI 1.00`,
  3 USB devices; the keyboard works in U-Boot.
- The PCIe bus is not cache-coherent with the ARM, so xHCI's DMA buffers
  need cache maintenance.
- The devicetree's PCIe `dma-ranges` carry an offset (inbound PCI
  `0x4_00000000` = CPU 0, 1 GB). Which inbound window the VL805's DMA
  really needs under Redox is not settled yet (row 410).

## Ethernet

- GENET v5 in the SoC with the BCM54213PE PHY on MDIO. Link at 1000 Mbit
  (row 411). MAC address from the devicetree, filled in by the firmware.
- U-Boot drives it as `ethernet@7d580000`.

## Serial console

The same pins as the 3B+ on the rear header: GPIO 14 (pin 8, TXD), 15
(pin 10, RXD), ground on pin 6, 3.3 V, 115200 8N1. The PL011 is again
taken by Bluetooth by default, so `dtoverlay=disable-bt` is needed. The
UART clock is 48 MHz. In the lab: `ttyUSB1` on homenodellm.

## Close relatives

**Pi 4 Model B** and **CM4**: same SoC and drivers. Differences: RAM up
to 8 GB, the Pi 4B's VL805 has its own SPI flash on newer boards (the
mailbox reset does no harm), the Pi 4B has the audio jack, CSI and DSI,
and the CM4 has optional eMMC instead of the SD card (EMMC2 drives
either). Devicetrees: `bcm2711-rpi-4-b.dtb`, `bcm2711-rpi-cm4.dtb`.
